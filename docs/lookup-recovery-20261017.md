# Photo-assisted catalogue recovery

Failed binder scans already offer a free catalogue search, but its initial form hid the photo whose printed name and number the seller needed to read. Closing that form also erased unfinished search fields.

The search view now includes a collapsible card photo. Touch devices initially focus the heading so the keyboard does not cover the reference before the seller chooses a field. Each physical row retains its unfinished game, name and number in memory. Retention is bound to the same account object and original file; confirming a printing clears it. Reopening never starts a request automatically. Exact-printing comparison and confirmation are unchanged.

Validation: 100 browser checks across portrait and landscape touch viewports, including photo availability, reopening, account isolation, no automatic catalogue request, existing stale-confirmation guards, unchanged physical-copy metadata, and no extra scans or credits. Asset fingerprints: 254 passed. Portrait search layout inspected using a synthetic card photo. No customer records or paid scans used.

This is a recovery usability improvement, not a claim of improved automatic recognition. Available owner uploads for the reported failures are app screenshots, not original full-resolution camera frames. Native iPhone keyboard/camera behavior and original-photo recognition accuracy remain separate acceptance work. Search fields are retained only in the current page lifetime.
