# Draft loading and workflow recovery — 2026-10-25

This follows PR124 and addresses reproducible draft-navigation and account-transition failures. It does not enable marketplace publication or change scanner recognition, prices, fees, billing or API contracts.

## Changes

- Draft list requests now belong to both the exact authentication session and the current list load. An old first page or pagination response cannot overwrite a newer list. Invalid-focus recovery runs only for the still-current request. A failed next page keeps the visible rows and cursor available for retry; a 401 clears private rows and counts and shows sign-in recovery.
- List and individual-draft reads have one 15-second deadline covering authentication, fetch and response decoding. A stalled read releases the spinner and offers a deliberate recovery action. Late tokens cannot send the expired request, and late responses cannot repaint it. Aborted fetches are not treated as completed writes; these are GET operations.
- Malformed successful responses produce a recoverable read error instead of an empty list. An individual read must return the requested draft ID before its fields and listing packet become usable.
- SDK sign-in/session replacement and sign-out clear the old account's draft rows, counts, selection, action panels, review details, packet copy payloads and local photo display. Stored drafts and photos are preserved. A newly signed-in account leaves the previous account's review and opens its own draft list.
- Late listing-detail refreshes cannot reopen an earlier draft. Delayed edit, conflict-reload, delete and local-photo callbacks cannot update a newer editor, draft or account. Photo cleanup following delete remains bound to the originating session. This preserves existing revision and delete-confirmation requirements.
- The ready verdict uses the theme's readable green rather than a fixed bright green that was difficult to read against the light-mode card.

## Boundaries

The deadline applies to draft GET reads. This pass does not add a deadline to every PATCH/DELETE or local photo operation, promise durable recovery of unsaved edits after closing a tab, or certify native Safari behavior. Authentication changes deliberately discard the retired session's displayed and unsaved action state; already saved records remain on the account.

Live scanner exact-printing accuracy still needs original labeled photos. eBay seller linking still does not establish market-wide sold-data access, and publishing/sales-sync gates remain unchanged. The existing runtime `DEP0169` deprecation warning remains outside this change.
